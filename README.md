# HOZAHA — סביבת ביקורת ועריכת כתב היד

## מסמך העבודה הפעיל
- המסמך המצטבר הפעיל היחיד נמצא בשורש: `כתב_יד_S027_P04596-P04602.docx`.
- קובצי DOCX היסטוריים נשמרים ב־`archive/docx/`; אין לעבוד עליהם במקום המסמך הפעיל.

## מבנה התיקיות
- `archive/conversations/` — תמלילי שיחות והעברות בין סשנים.
- `archive/docx/` — גרסאות Word היסטוריות, עותקי ביניים ותיקוני גופן.
- `editorial-reports/` — בחינות מושגיות ועיוניות לפי טווחי פסקאות.
- `editorial-reports/word-comment-logs/` — דוחות הוספת הערות Word, תיקוני הערות וביקורת מבנית.
- `source-verification/` — אימות מקורות, מראי מקום והפניות פנימיות.
- `review-windows/` — חלונות טקסט לחומרי ביקורת לפי טווחי פסקאות.
- `project-management/` — יומן ההמשכיות, מפת מצב, רשימות בדיקה ותכנית העריכה.
- `project-management/מדיניות_עריכה_חזרות_הקדמה_וגוף.md` — מדיניות המחבר המחייבת לגבי חזרות מכוונות בהקדמה ובגוף הספר.
- `audit/` — כלי ביקורת וחילוץ קריאה בלבד.
- `review/` — כלי הטמעת ותיקון הערות Word.
- `review_batches/` — הגדרות אצוות הערות.
- `scripts/` ו־`tests/` — כלי עזר ובדיקות.
- `.github/workflows/` — תהליכי האוטומציה.

## כללי שימור
1. אין לשנות את גוף כתב היד; תוספות עריכה נעשות כהערות Word בלבד, אלא אם ניתנה הוראה מפורשת אחרת.
2. לפני יצירת DOCX מצטבר חדש יש לוודא שמסמך הבסיס הוא האחרון ושכל ההערות הקודמות נשמרו.
3. יש לאמת 4,603 פסקאות ואת גיבוב גוף כתב היד מול הערך המתועד ביומן ההמשכיות.
4. אין למחוק גרסאות היסטוריות; יש להעבירן לארכיון תוך שימור ה־Git blobs.
5. יש לעדכן את יומן ההמשכיות לאחר שינוי מבני או עריכתי משמעותי.

לפרטי מצב והמשך העבודה ראו `project-management/יומן-דחיפות-והמשכיות.md`.
