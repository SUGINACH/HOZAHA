# כלי ביקורת וחילוץ

הסקריפטים בתיקייה זו בודקים את מבנה קובצי DOCX ומחלצים חלונות טקסט לביקורת. הם פועלים בקריאה בלבד ביחס למסמכי המקור.

- חלונות ביקורת נכתבים אל `review-windows/`.
- מקורות DOCX היסטוריים נקראים מתוך `archive/docx/`.
- מחלצי החלונות פועלים לפי נקודות הביקורת שבענף, עד לזנב כתב־היד P04596–P04602. מחלץ הזנב העדכני הוא `extract_P04596_window.py`, והוא קורא את המסמך המצטבר הקודם מן הארכיון.
- `extract_P04596_window.py` קורא את המסמך המצטבר הפעיל שבשורש, ולא עותק ארכיוני; הוא מסרב להפיק חלון אם חסרות בו תוויות הערות הזנב S-20261109-165–169.
- `inspect_docx.py` סורק את כל קובצי ה־DOCX שבשורש וב־`archive/docx/` באמצעות ארבעה תהליכוני Python נפרדים (`ProcessPoolExecutor`), מפיק דוח אל `editorial-reports/word-comment-logs/` ומעדכן את יומן ההמשכיות ב־`project-management/`. זמן הריצה המרבי הוא 90 דקות, משום שהסריקה הקודמת נעצרה במגבלת 30 דקות לפני השלמת 119 הקבצים.
- בדוח נרשמים בנפרד ה־commit שנבדק בפועל (`git rev-parse HEAD`), לאחר רענון `origin/main`, וה־commit שהפעיל את ה־workflow. אין להסתמך על `GITHUB_SHA` לבדו לאחר `git reset --hard origin/main`, משום שהוא מציין את commit ההפעלה המקורי ועלול להיות מיושן.
- ה־workflow `.github/workflows/audit-manuscript-docx.yml` מריץ את בדיקת המסמכים בתהליכונים מקבילים ואת 38 מחלצי חלונות הביקורת בשלושה תהליכונים מקבילים, עד P04596; רק לאחר השלמתם הוא שומר את הדוחות והחלונות שנוצרו. הביקורת היא קריאתית בלבד.
- אין להוסיף נתיב קובץ חדש בלי לעדכן גם את ה־workflow המתאים ולוודא שהקובץ קיים.

הביקורת המבנית אינה משנה קובצי DOCX ואינה תחליף לביקורת עיונית או לאימות מקורות.
